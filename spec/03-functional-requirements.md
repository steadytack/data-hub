One testable statement per requirement. Priority is Must, Should or Could: Must for Phases 0 and 1, Should for Phases 2 and 3, Could for the parked Phase 4 items (D-007). ## Workflows and states
- **Product:** registered (manifest loaded) → running → silver ready → promotion-ready (gate passes) → published (gold view live) → refreshed (new versions). A failed blocking check sets the tier, not the state: the last published version stays live (FR-022).
- **Known issue:** open → triaged → accepted or being fixed → resolved (FR-007). Detection, measure and fix link are recorded along the way.
- **Run:** queued → running → succeeded, failed or skipped, per step and per run (FR-041).
- **Tier:** proposed by the score, capped (RULE-006), optionally overridden by a steward, signed off for Certified; every change audited.
- **Phase 2 builder draft:** draft (branch) → reconciled → committed (FR-048).
- **Phase 3 access request:** requested → approved (grant created) or declined (FR-103).

## Errors and edge cases
- Source unreachable or the version file missing: the run fails with a known issue; nothing partial is kept; the last published version is served.
- A huge file: loading streams features; file size and load time are recorded (FR-010) for the performance question (NFR-003, NFR-004).
- Two runs of one product at once: the second waits (one active DAG run per product).
- A manifest edited while a run is in progress: the change applies to the next run.
- Invalid geometry that repair cannot fix: the row is kept, flagged and counted, and a warning issue opens.
- MCP query that is not one SELECT over published views: refused before it runs (SEC-005).
- A user deactivated mid-session: the next request is refused on every door, and their database login is disabled.

## Import, export and background behaviour
- **Import:** download (FR-010), upload from Phase 1 (FR-013), API and Postgres or SQL Server pulls from Phase 1 (FR-015, FR-017, FR-119); OGC API ingest, the network runner and change-data-capture parked (FR-016, FR-120, FR-125). Every source is a connector (FR-128).
- **Export:** CSV and GeoPackage bundles with a sidecar and version file (FR-094, FR-095).
- **Background:** Airflow runs each product's DAG on its schedule, the weekly version check (FR-043), the nightly backup (FR-100), hourly grant expiry (RULE-016) and the monthly audit purge after 12 months (NFR-009).
